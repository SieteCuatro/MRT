# In-Depth GUI & Widgets Guide (`mrt-app`)

[`crates/mrt-app`](../crates/mrt-app) is the binary crate (`mrt`) that renders the GPU-accelerated desktop interface using `eframe` / `egui` (`0.29`) and handles CLI flags (`--mcp-server`, `--version`, `--help`).

---

## 1. Non-Blocking Async Architecture & Live MCP Synchronization

Terminal commands, HTTP requests, web fetches, port scans, MCP tool calls, and AI queries must **never** block the 60fps GPU render thread.

`MrtGuiApp` uses a channel-driven architecture:
1. `MrtGuiApp` owns a multi-threaded `tokio::runtime::Runtime`, an `std::sync::mpsc::{Sender<AsyncWorkerEvent>, Receiver<AsyncWorkerEvent>}` for background worker events, and a `Receiver<GuiUiCommand>` for live commands sent by external MCP agents.
2. On startup, `MrtGuiApp` starts the **Live GUI Bridge** (`start_gui_bridge_listener`) on `127.0.0.1` so external `mrt --mcp-server` clients can connect to the running window.
3. On every frame, `MrtGuiApp::update()` calls:
   - `self.process_async_events()`: Handles streaming stdout/stderr chunks, completed `CommandBlock`s (persisted to SQLite history and mirrored to MCP state), AI command proposals, Explorer directory listings, and external MCP server registrations.
   - `self.process_mcp_ui_commands()`: Applies live MCP agent actions (`SyncFromMcp`, `SetInputDraft`, `SetMosaic`, `SetExplorer`, `SetComparison`) directly to the GUI state.
   - `self.sync_mcp_from_gui()`: Keeps `MrtMcpServerState` tabs, active tab ID, CWD, and blocks synchronized with user interactions in the GUI.

## 2. Key UI Components

### 2.0 Visual Language ("Graphite Calm", `theme.rs`)
Neutral graphite surfaces, one soft accent (`#8EA2FF`), generous radii (10 px buttons, 14 px blocks, 18 px composer and modals) and a 4 px spacing grid. All colors live in `theme::Palette`, radii in `theme::Radius`, and shared building blocks (`chip`, `icon_button`, `ghost_button`, `primary_button`, `secondary_button`, `panel_frame`, `section_label`) in `theme.rs`. Layout primitives (`nav_row`, `tab_row`, `search_pill`, `palette_row`, `brand_mark`, `centered_column`) live in `widgets/chrome.rs`. The block stream and the composer are capped at `STREAM_MAX_WIDTH` (880 px) and centered.

### 2.1 Sidebar & Header (`app.rs`: `render_sidebar`, `render_header`)
- **Sidebar**: **+ New tab** (popup listing every discovered shell: `Windows PowerShell`, `Command Prompt / Batch`, `Git Bash`, `WSL`, etc.), **Search history**, the **Tabs** list (each row shows the folder, shell and an activity indicator — idle, running spinner, progress ring with percentage, pulsing "waiting for input", finished or failed — with a tooltip; hover to reveal `×` to close), and **Workspace** toggles for **Explorer**, **Runbooks**, **History**, **MCP Hub**, **Toolbox**, **Mosaic** and **Notifications**. A tab row shows a numbered accent badge while it has finished commands you have not seen (see §2.5). A status card at the bottom shows the Safety Gate and the MCP bridge port. The `«` / `»` button collapses the sidebar to a 60 px icon rail.
- **Header**: The active tab's working directory, a search pill that opens the **Command Palette** (`Ctrl+K`), and split controls.
- **Split Panes**: Split any active tab horizontally or vertically (header buttons, the palette, or `:split`, `:split-h`, `:split-v`, `:unsplit`). Each pane maintains its own independent command block history, shell execution stream, and focus state.
- **Mosaic** (`widgets/mosaic.rs` layout engine + `render_mosaic`): shows every terminal at once, filling the screen. Arrangement presets: **Grid** (1–6 per row; the last row stretches), **Columns** (all side by side), **Rows** (all stacked) and **Focus** (the active terminal large on the left, the rest stacked beside it; clicking a terminal makes it the main one). Drag a tile header onto another tile to move it there; double-click the title (or **Open**) to leave Mosaic on that terminal. Each tile has its own activity indicator (same states and tooltip as the sidebar), shell switcher, compact output and command input; layouts drop to fewer columns, and scroll, instead of shrinking tiles below a readable size. A tab running an interactive program (overlay or pane session; the active pane's wins) shows that program's screen in its tile instead of its output: `draw_mosaic_tui` paints the session's `TermSnapshot` read-only with a monospace font sized so the columns fit (5-12 pt), without resizing the program's PTY. Agents can pick the arrangement with `mrt_control_gui`’s `mosaic_layout`.
- **Composer**: A floating card at the bottom with the command input (`#` prefix asks AI), the per-tab **Active Shell Switcher**, the Safety Gate indicator and a round Run button. AI command proposals appear as a card just above it with **Run** / **Dismiss**.
- **Empty state**: A new tab shows a short welcome with the main shortcuts.

- **Tab activity** (`mrt_core::activity` + `widgets/activity.rs`): every `TerminalTab` owns an `ActivityTracker`. `spawn_shell_command` and the TUI overlay call `command_started`; streamed output chunks (`process_async_events`) and new PTY output (`process_tui_session`) go to `feed_output`, which parses `OSC 9;4` progress and MRT's `OSC 678;status=…` sequence and keeps the last plain-text lines; `BlockCompleted` / TUI exit call `command_finished`. When a process sample arrives (Task Manager, `:top`, watches), `observe_activity_processes` passes the process-tree names of running commands so agent CLIs launched through wrappers are recognised. `tab_status()` returns `tracker.snapshot(now)`; `paint_activity_indicator` draws it (dot, spinner, progress ring, pulsing waiting dot) in `tab_row` and the Mosaic tile header, and the app requests a repaint every 150 ms while any tab is running so spinners turn and quiet-period heuristics can fire. The same snapshot is copied into `McpTabSession.activity` by `sync_mcp_from_gui`. See the [User Guide](USER_GUIDE.md#tab-activity-status) for the states, heuristics and the escape sequence.

### 2.2 Command Block Renderer (`widgets/block_view.rs`)
Each `CommandBlock` is rendered as a rounded card (a red-tinted border marks non-zero exit codes):
- **Header Row**: Status icon (✔ / ✖ / spinner), command text (truncated, full text on hover), structured-output chip (`JSON`, `Table`, `HTTP`, `Markdown`), `exit N` chip for failures, duration and time (hover for shell and CWD), and quiet actions: **Diagnose** (failed commands), **Raw / Structured** toggle, **Copy**, **Rerun**, **Diff** (compare with previous run) and **Report** (sanitized Markdown bug report for failed commands).
- **Inline Diagnosis**: AI explanations render inside the block, with the suggested fix command and **Run** / **Copy** buttons.
- **Specialized Viewers**:
  - `render_json_tree`: Recursive collapsible `egui::CollapsingHeader` tree with syntax-colored keys, strings, numbers, booleans, and nulls.
  - `render_structured_table`: Striped `egui::Grid` with a real-time row substring filter box. Cells in `PID` / `PPID` columns are links (`BlockAction::InspectProcess`) that open the process in the Task Manager.
  - **■ Stop** (running blocks only, `BlockAction::StopBlock`): ends a live `:top` block, or force-stops the command's whole process tree using the shell PID recorded by `execute_command_streaming_with_pid`.
  - `render_http_exchange`: Method/URL header, color-coded HTTP status & latency badge, collapsible response headers, and embedded JSON tree.
  - `render_markdown_block`: Styled `#` / `##` / `###` headings and bullet lists.
  - `render_ansi_spans`: Converts `Vec<AnsiSpan>` into an `egui::text::LayoutJob` with per-span foreground/background RGB colors, italics, and underlines, through `widgets/links.rs` (`render_spans_with_links`), which also makes links clickable (Mosaic tiles use the same helper).
- **Links (`widgets/links.rs`)**: OSC 8 hyperlinks plus URLs and `path:line[:col]` locations found by `mrt_core::detect_links` are underlined in the accent color. Hovering shows the target; **Ctrl+click** (**Cmd+click** on macOS) opens it. URLs go to the browser (`ctx.open_url`) if their scheme is `http`, `https`, `ftp`, `mailto` or `file`; other schemes are shown but never opened. File paths are resolved against the block's OSC 7 directory (or its starting cwd) and opened in `$VISUAL` / `$EDITOR` with the right line syntax (`code --goto`, `subl path:line:col`, `vim +line`, `nano +line,col`, `emacs +line:col`). Terminal editors (`vim`, `nvim`, `nano`, `hx`, `micro`, `kak`, `emacs -nw`) are run in the Interactive TUI overlay with `:tui` (`BlockAction::Rerun`). With no editor set, the OS opener is used (`explorer.exe`, `open`, `xdg-open`). Failures show a dismissible line under the output.
- **Clipboard prompt (OSC 52)**: When a command asks to write the clipboard, the block shows a prompt with the character count and a preview, and **Allow** / **Deny** buttons (**Deny all** when there are several). Nothing is copied until you click **Allow**. Mosaic tiles only show a count; open the block in the normal view to answer.
  - `render_comparison`: Structured diff viewer supporting canonical JSON diffs (key reordering produces 0 diff), port snapshot delta breakdowns, and line-by-line unified diffs (`similar::TextDiff`).

### 2.3 Side Panels (`widgets/side_panels.rs` & `widgets/runbooks.rs`)
- **MCP Hub Panel (`render_mcp_side_panel`)**: Displays the **Live GUI Bridge** status (`127.0.0.1:<port>`) with a one-click **Copy MCP Config** button, lists connected MCP servers (`mrt-native-mcp` + external `stdio` and HTTP servers; HTTP rows show the URL and header names, never header values), expandable tool descriptions, custom JSON argument editor, one-click **Invoke Tool** buttons, one-click **Server Presets** (Filesystem, Git, Memory Graph, SQLite, Fetch), and a **Connect External Server** form with a **Transport** switch: `stdio` asks for **Cmd** and **Args**, `HTTP` asks for a **URL** and a masked **Headers** box (one `Name: value` per line, **Show** to reveal). Invalid header lines appear as a failed server row.
- **Toolbox Panel (`widgets/toolbox.rs`: `render_toolbox_side_panel`)**: One panel with a tab strip; `SidePanelState::toolbox_tab` (`ToolboxTab::Network` / `ToolboxTab::TaskManager`) remembers the last tab. Each tab has its own render function in its own file, so a new tool family is a new `ToolboxTab` variant plus a widget file. Open it from the sidebar, `:toolbox [network|task-manager|close]`, the Command Palette, or `mrt_control_gui`'s `toolbox` argument.
  - **Network tab (`side_panels.rs`: `render_network_tab`)**: Interactive forms for the HTTP/REST Inspector, Readable Webpage Extractor, Local Port Scanner, DNS Resolution & Latency Tracer, and WebSocket Inspector. The last port scan (`SidePanelState::last_ports`, filled from any `:ports` block) is listed with each PID as a link that opens the Task Manager on that process.
  - **Task Manager tab (`widgets/task_manager.rs`: `render_task_manager_tab`)**: Live process list (refreshed every 2 s while visible and **Live** is on) with filter, sort, **Tree**, and **MRT only** toggles, per-row CPU sparklines, and MRT-owned processes highlighted. Selecting a row shows command line, parent (clickable), user, status, uptime, CPU/memory sparklines, child count, listening ports, and **Stop** / **Force stop** / **Stop tree** (through the Safety Gate), **Details** (`:proc`), **Watch** (`:watch-proc`) and **Copy PID**. **Snapshot to tab** runs the current view as a `:ps` block; **Compare with last snapshot** also diffs it with the previous `:ps` block. Samples come from one `SharedProcessSampler` (shared with the MCP server) via the background `AsyncWorkerEvent::ProcessSnapshot` event, which also refreshes live `:top` blocks and evaluates `:watch-proc` watches; background events do not count towards the busy spinner.
- **Runbooks Panel (`render_runbooks_panel`)**: Offline SQLite-backed manager for saved command sequences (`Runbook` / `RunbookStep` in `history.rs`). Supports creating and editing runbooks, picking steps from command history (or adding manual steps), reordering steps (`^` / `v` / `x`), selecting per-step shell and working directory, previewing steps before execution, and replaying step-by-step via `ActiveRunbookReplay` (routing each step through the Safety Approval Gate, rendering each output as a `CommandBlock`, and stopping on the first non-zero exit code).

### 2.4 Modals & Overlays (`app.rs`)
- **Inline TUI panes (`MrtGuiApp::pane_tuis`)**: In a split tab, `submit_input` creates the session with `pane: Some(active_pane_idx)` (unless that pane already has one) instead of opening the overlay. The split-pane renderer calls `draw_pane_tui` in place of the pane's block list: a header with the program's title and an **Exit** button, then `ActiveTuiSession::draw_surface`, the same sizing, painting, mouse and selection code as the overlay. `focused_tui()` decides who gets the keyboard: the overlay if open, else the active pane's session (none while the command palette, the Safety Gate or Mosaic is shown); `handle_keybindings` and the composer use it in place of `active_tui.is_some()`. A press inside an unfocused pane's terminal focuses that pane; it is read from the frame's `PointerButton` events, because synthetic clicks deliver press and release in one frame and `response.clicked()` did not fire. `process_tui_session` pumps every session each frame and `finish_tui` stores a finished one as a block in its pane; sessions whose tab or second pane is gone are killed without a block. The terminal widget uses a stable id per tab and pane (`paint_terminal`'s `id`), and `cell_size` measures a 100-character run, since egui's text layout advance is slightly larger than `glyph_width` and the last column was clipped.
- **Interactive TUI Mode Overlay (`ActiveTuiSession`)**: When launching interactive console tools (`vim`, `vi`, `nvim`, `nano`, `htop`, `lazygit`, `less`, etc., or via `:tui <cmd>`), MRT opens a full-screen PTY overlay backed by a `TerminalEmulator`. Every frame (`process_tui_session`, 30 ms repaint) it drains new PTY output into the emulator and the tab's activity tracker, flushes an expired synchronized update, and writes the emulator's replies (device attributes, cursor position, size) back to the PTY. `render_tui_overlay` measures the monospace cell (`term_view::cell_size`), fits whole cells into the window (`grid_dims`), resizes the emulator and the PTY when that changes, and paints the snapshot with `widgets/term_view.rs` (style runs per row, wide characters drawn alone, block/underline/beam cursor, an outline cursor when the window is unfocused). The window title follows the program's OSC 0/2 title. Keys not bound to MRT actions go through `term_input::encode_event` (xterm sequences, application cursor mode, Alt+letter, bracketed paste) and are written with `InteractivePty::send_bytes`. egui-winit reports Ctrl+C and Ctrl+X only as `Event::Copy` / `Event::Cut` (no key event); `encode_event` turns them into `^C` / `^X` outside macOS, and `process_tui_session` instead copies the selection (`term_view::selection_text`, `ctx.copy_text`) when there is one, when Shift is held (Ctrl+Shift+C), or on macOS (Cmd+C). A left drag over the grid selects text when the program has no mouse mode or Shift is held (`ActiveTuiSession::selection`, shaded by `term_view::paint_selection`); otherwise `forward_tui_mouse` turns pointer presses, releases, cell-to-cell motion and wheel notches over the grid into mouse reports (`encode_mouse`, SGR 1006 or X10, filtered by the program's 1000/1002/1003 mode), or into arrow keys for the wheel on an alternate screen with mode 1007. The backdrop is in the `Middle` layer and the window in `Foreground`, like the other modals. The terminal widget keeps keyboard focus with a focus-lock filter for Tab, arrows and Esc, so keys reach the program and not the command input underneath. On Windows, `portable-pty` opens ConPTY with `PSEUDOCONSOLE_RESIZE_QUIRK`, so ConPTY does not repaint after a resize and expects the terminal to grow like conhost (blank rows at the bottom); before resizing, the overlay moves the emulator's history into `ActiveTuiSession::saved_history` so alacritty cannot pull it back onto the screen. When the session ends, its block stores `saved_history` plus `TerminalEmulator::text_with_colors()` (history and main screen with SGR colors), never the raw transcript, whose cursor movement would show as blank lines. Exiting cleanly or pressing `Ctrl+Q` ends the session.
- **MRT Safety Approval Gate**: A warning card anchored just above the composer that intercepts commands requiring approval, shows the risk level, reason, command, target shell and working directory, and requires explicit **Run anyway** or **Cancel** (`Esc` also cancels). Process stop requests (`:kill`, Task Manager buttons, MCP `mrt_kill_process`) use the same card with `PendingSafetyApproval::kill` set: it lists the targets, method (graceful / force) and child count, and the confirm button reads **Stop process**.
- **Universal Command Palette (`Ctrl+K` / `Ctrl+P`)**: Searchable modal grouped into **Actions**, **Layout**, **Tools**, **Processes**, **Ask AI** and **Shells**. **Actions** lists every bindable action with its current key binding (or its action name, ready to bind in `[keybindings]`), and problems in the user's `[keybindings]` table are listed above it. `Enter` runs the first match (or the typed text as a command when nothing matches); `Esc` closes it.
- **Key handling (`keymap.rs`)**: Every key press goes through a `KeyResolver` before egui widgets or the TUI PTY see it. It turns chords, chains (`ctrl+a > c`) and named key tables into `Action`s, shows a small indicator while a chain or table is waiting for the next key, and passes unbound keys through. The default keymap reproduces MRT's built-in shortcuts; `config_runtime.rs` rebuilds it from the config file's `[keybindings]` table on load and on every reload.
- **Persistent shells (`shell_pool.rs`)**: `spawn_shell_command` first asks the `ShellPool` for the tab's `ShellSession` (keyed by tab and shell id; started on first use in a blocking task). When it is idle the command runs there through `run_in_session` (a `cd` first if the tab's folder changed), streaming output into the block like before; otherwise it falls back to `execute_command_streaming_with_pid`. The shell's PID is recorded for the Task Manager. **Stop** (`stop_block`) sends Ctrl+C to the session and, if the block is still running a second later, terminates the shell's child processes. Closing a tab ends its sessions; `terminal.persistent_shell` turns the pool on and off (unit tests opt in with `shell_pool.set_enabled(true)`).
- **Large blocks (`block_view.rs`)**: `render_ansi_spans` draws only the last `RENDERED_LINES_STEP` (2,000) lines, found from the end by `tail_spans` so the cost depends on the lines shown, not the output size; **Show 2,000 more** / **Show all** raise the count (egui temp data per block). A find match in the hidden part raises it until the match is shown, and the find index is shifted by the matches above. Mosaic tiles draw the last 200 lines. Blocks with `truncated_bytes > 0` say how much output was dropped.
- **Inline images (`block_view.rs`)**: when a block has images, `render_ansi_spans` cuts the shown spans at each image's anchor (`split_spans_at`), draws each text segment as its own galley (find indexes are shifted per segment) and the image between them as an `egui::Image` whose texture is cached in egui temp data per block and image. `inline_image_size` honours requested cells / pixels / percent, otherwise uses the pixel size divided by `pixels_per_point`, then fits the width and 600 points of height.
- **Repaint policy**: worker events (`tx`) and MCP bridge commands (`gui_cmd_tx`) go through `waking_channel`, whose forwarding thread calls `wake_ui()` (`ctx.request_repaint()` on the context saved by `set_ui_context` at startup). The UI therefore repaints every 50 ms only while commands run, 30 ms while a TUI is open, and otherwise once per `IDLE_REPAINT` (1 s, for the config watcher) or when input or an event arrives.
- **Fonts (`fonts.rs`)**: `config_runtime::update_config` installs fonts from `terminal.font_family` / `terminal.font_fallback` whenever they change: `resolve_font` accepts a file path or matches a family name against font file names in `system_font_dirs()` (regular face first), and `build_font_definitions` puts the main font, the fallbacks and platform symbol fonts at the front of egui's monospace family. Missing fonts are reported in the config notice.
- **Grid search and agent terminals**: in grid copy mode `/` starts `GridSearch` (text events go to the query); `Enter` runs `TerminalEmulator::search` over history and screen and `reveal_line` scrolls the view (`set_view_offset`) to the match; `n` / `N` step through matches; moving past the top or bottom row, `PgUp` and `PgDn` scroll the view; leaving copy mode resets it. `draw_surface` shows the search status in the top-right corner. `:agents` toggles `render_agent_ptys`: `update_agent_screens` keeps one `TerminalEmulator` per MCP PTY fed with `transcript_since`, drawn read-only with `paint_terminal`.
- **Grid copy mode and images**: `Action::CopyMode` with a focused TUI calls `ActiveTuiSession::start_grid_copy`; while `grid_copy` is set, `forward_keys` hands keys to `grid_copy_keys` (`copy_mode::GridCopy`) and sends nothing to the PTY, and the cursor / selection is shown through `selection`. `draw_surface` draws `term.images_on_screen()` over their cells with textures cached in `image_textures` (dropped when an image leaves the screen).
- **Themes (`theme.rs`)**: `Palette::X()` reads the active `ThemeColors` (`set_theme_colors`); `GRAPHITE_CALM` and `HIGH_CONTRAST` are built in, `resolve_theme` maps `terminal.theme` to one of them or loads a file through `mrt_core::load_theme_file`, and `theme_from_spec` derives UI colors from a terminal scheme (`derive_from_terminal`) before applying `[ui]` overrides. `config_runtime::update_config` applies a changed theme, sets the ANSI palette (`mrt_core::set_ansi_palette`) and rebuilds egui's visuals with `apply_mrt_theme`.
- **Quick terminal**: `GuiUiCommand::SetWindow` (from `mrt_control_gui`'s `window` argument, used by `mrt quick`) sets `pending_window`; `apply_window_action` un-minimizes, places (with `terminal.quick_dropdown`) and focuses the window, or minimizes it.
- **Accessibility**: the TUI surface's response carries `WidgetInfo` with `TerminalEmulator::screen_text()` (computed only when AccessKit is active).
- **Worktree tabs**: `:worktree <branch> [base]` calls `open_worktree_tab`, which uses `mrt_core::worktree::create` and opens (or focuses) a tab with `TerminalTab::worktree` set; `:worktree list` writes a table block. `close_terminal` on a worktree tab stores a `PendingWorktreeClose` (with `worktree::changed_files`) instead of closing, `render_worktree_close_prompt` draws the prompt, and `finish_worktree_close` closes the tab through `close_terminal_now` and, when asked, runs `worktree::remove` and posts the result as a block in the tab that becomes active. The field is mirrored to `McpTabSession::worktree` (both ways, so tabs agents open with `mrt_create_tab` get the prompt too) and saved in `layout.json`. `render_header` adds a second row for a worktree tab (the `branch → base` chip and Review / Merge / Open PR / Discard buttons, which submit `:worktree review|merge|pr|discard`). `worktree_action` writes the review block (`worktree::review`, shown as raw text with the diff's colors) or opens the Safety Gate with `requires_approval: true` whatever the config: merge and pr as Moderate shell commands built for the tab's shell (`merge_command`, `pr_command`, after `merge_blocker` / `pr_blocker`), discard as Critical with `PendingSafetyApproval::worktree_discard`, which `approve_pending_command` hands to `discard_worktree` (close the tab with `close_terminal_now`, then `worktree::discard`).
- **AI usage**: `AsyncWorkerEvent::AiCommandReady` (with `proposal.usage`) and `AiUsageRecorded` (from `spawn_assist`) go through `record_ai_usage`, which adds to `TerminalTab::ai_usage` and `ai_usage_session`. The suggestion card shows `usage.summary()` next to the provider, the sidebar footer shows the session total, and `:ai-usage [reset]` writes `ai_usage_report` as a table block.
- **Idle tabs for agents** (`mrt-mcp/src/server.rs`): `mrt_run_command` with `idle: true` calls `pick_idle_tab`, which compares `worktree::checkout_root` of each tab's folder with the one asked for, skips sandbox tabs and busy ones (activity running, progress or waiting for input, a block without an exit code, or in `mcp_busy_tabs`), and otherwise pushes a new `McpTabSession` that `SyncFromMcp` turns into a GUI tab. Every `mrt_run_command` marks its tab in `mcp_busy_tabs` until it returns (`BusyGuard`).
- **`:assist` and sandbox tabs**: `spawn_assist` syncs the MCP mirror, pushes a running `mrt-ai` block, and runs `mrt_ai::run_assist` on the runtime with a tool executor that calls `mrt_mcp::handle_mcp_jsonrpc` on `local_server_state`; steps stream into `running_output`, and the finished block carries `ai_explanation` / `ai_suggested_fix`. `open_sandbox_tab` sets `TerminalTab::sandbox_root`: `submit_input` then uses it as the cwd and asks for approval for every non-Safe command, completions never move the tab's folder, `sync_mcp_from_gui` mirrors it to `McpTabSession::sandbox_root`, and layouts save it.
- **Copy mode (`copy_mode.rs`)**: `CopyMode` (block index, line, optional anchor) with `apply(CopyKey, &blocks)` and `selection_text`; `update_copy_mode` runs after `handle_keybindings`, removes copy-mode keys and all `Event::Text` from the input so the prompt never sees them, and draws the panel with `copy_mode::render`.
- **Named actions and hooks (`hooks.rs`)**: `Action::RunNamed` → `run_named_action` (one line → `submit_input`; several → an ad-hoc runbook, whose `:` steps `advance_runbook_replay` runs at once). `named_palette_actions` adds them to the palette; `apply_config_side_effects` turns `key =` into `run:<name>` bindings. `process_async_events` collects `HookEvent`s on `BlockCompleted` (`command_finished` / `command_failed`, `cwd_changed`) and `open_new_tab` fires `tab_opened`; `hooks::fire` spawns each matching hook through the default shell with `CREATE_NO_WINDOW`, `MRT_*` variables and a 60 s timeout (`raw_arg` for `cmd.exe`).
- **Broadcast**: `TerminalTab::broadcast` (`:broadcast`, `toggle_broadcast`). `forward_keys` returns the bytes it sent; in `process_tui_session` the focused pane's bytes are sent to the tab's other pane sessions, and `draw_pane_tui` shows a **broadcast** marker.
- **Session host (`session_host.rs`)**: `connect_session_host` (startup, `terminal.session_server`) runs `ensure_host` (start `mrt session-host` detached if `session-host.json` does not answer) and sends `AsyncWorkerEvent::HostJobs`; `reattach_host_jobs` turns each job into a running block followed with `HostClient::follow`. `spawn_shell_command` sends local, non-remote commands to the host (`HostRequest::Run`, then `follow`), falling back to the in-window pool when the host is unavailable. `host_blocks` routes Stop to the host and keeps host commands out of `has_running_work`. Closing a tab sends `CloseTab`; `mrt quit` sends `Shutdown`. `layout.rs` saves tab ids so jobs find their tab.
- **Background and single instance**: `handle_close_request` turns a close with `has_running_work() > 0` into `CancelClose` + hide (minimize outside Windows) and sets `IN_BACKGROUND`; `gui_command_channel`'s thread calls `native_show_window` (Win32 `ShowWindow` on the `HWND` saved at the first frame) for `SetWindow` show/toggle/quit while hidden, because the UI loop may not run then. `apply_window_action` handles `quit` (`quit_requested` + `Close`). `cli::handoff_to_running_instance` runs before `eframe::run_native`. `GuiUiCommand::SafetyDecision` answers `pending_safety` only with `safety.remote_approvals`, and `sync_mcp_from_gui` mirrors the prompt to `pending_approval`.
- **Session server (`server.rs`)**: `mrt server` refuses to start when the discovery file's endpoint answers `ping`, then serves a fresh `MrtMcpServerState` with `start_gui_bridge_listener(.., discovery: true)` until Ctrl+C and removes the discovery file.
- **Layout restore (`layout.rs`)**: `capture_layout` turns the tabs into a `SavedLayout` (title, shell id, cwd, remote args, split direction / shell / cwd, active tab, Mosaic). `persist_layout` runs every frame but compares at most every 3 s and writes `layout.json` (temporary file + rename) only when the layout changed; `on_exit` forces a save. `MrtGuiApp::new` calls `restore_layout` when `terminal.restore_layout` is on (never in tests), mapping missing shells to the default shell and missing folders to the start folder.
- **Command-line control (`cli.rs`)**: `mrt list|send|capture|split` parse their flags (`parse_args`), map to one MCP tool (`tool_request`), send a single `tools/call` over the bridge with `try_forward_jsonrpc_to_gui`, and print the result (`render`) with documented exit codes (`EXIT_USAGE` 2, `EXIT_NO_WINDOW` 69, `EXIT_TOOL_ERROR` 70, or the command's code for `send`).
- **Remote tabs (`:ssh`)**: `open_remote_tab` creates a `TerminalTab` with `remote: Some(ssh args)` and runs `hostname` in it. `spawn_shell_command` sends a remote tab's commands to `shell_pool::run_remote`, which connects through `ShellPool::acquire_remote` (key `(tab, "ssh")`; a busy session is reused and the command queued; there is no local fallback) and runs them with `run_in_session(.., cwd: None, ..)`. A failed connection becomes the block's text (`remote_failure_message`) and the next command retries. TUI commands in a remote tab are wrapped by `remote_tui_command` (quoted for the local shell) and run from a local temp folder. `render_explorer` shows a notice for remote tabs.
- **Find in output (`find.rs`, `render_find_bar`)**: The `find` action (Ctrl+F) opens a bar at the top of the central panel. `count_matches` runs `match_ranges` (ASCII case-insensitive, non-overlapping) over each block's `plain_output`; `render_find_bar` stores a `find::Highlight` (query, current block and match, scroll flag) in egui's temporary data, which `render_ansi_spans` passes to `render_spans_with_links` as a `FindView`. Matching segments get an amber background (solid for the current one), and the current match is scrolled to with `scroll_to_rect_animation(.., ScrollAnimation::none())`, repeated for three frames; the animated scroll did not reach matches far up a long block. While the bar is open, the block lists stop sticking to the bottom, since `stick_to_bottom` overrides programmatic scrolls.
- **Config notice (`config_runtime.rs`: `render_config_notice`)**: A dismissible line under the header that shows config warnings, or, when a file has an error, that MRT kept the last good settings and why.

### 2.5 Command Notifications (`notifications.rs`)
`CommandNotifier` is called once per frame from `update` (`notifier.update(ctx, &tabs, active_tab, mosaic)`). It walks every tab's blocks (primary and split pane) and keeps the ids of finished blocks it has handled, so it sees each completion once whatever produced it: shell commands, runbook steps, built-ins, and the TUI overlay (whose block is pushed already finished). Blocks that exist on the first frame are never announced; a block that goes back to running (live `:top`) is announced again when it ends.

- **Decision** (`should_notify`): notifications are enabled, the block's `duration_ms` is at least `threshold_secs`, and either the window is unfocused or minimized (`ViewportInfo::focused` / `minimized`) or the block's tab is hidden (not the active tab, and Mosaic is off).
- **Badge**: a finished block in a hidden tab increments that tab's unseen count regardless of duration; the count is cleared once the tab is visible while the window has focus. `render_sidebar` paints it with `paint_badge` after each `tab_row`.
- **Delivery**: `notify-rust` on a short-lived thread (title: finished / failed with exit code; body: command truncated to 80 characters, duration, tab name). On Linux (freedesktop D-Bus via `zbus`, no system libraries needed) a click on the notification sends the tab id back over a channel; the next frame un-minimizes and focuses the window and switches to the tab. The Windows (WinRT toast) and macOS backends of `notify-rust` do not report clicks, so there the notification is informational. Unit tests build the notifier with desktop delivery off and test `observe` directly.
- **Settings**: `NotificationSettings { enabled, threshold_secs }` (default on, 10 s), edited in the **Notifications** window opened from the sidebar. The config file's `[notifications]` section sets them on load and on every reload; edits in the window last until the next reload.
